## איך המערכת מתחברת

זמינות עובדים: Google Form → גיליון תשובות Google Sheets → Make → מאגר זמינות → קריאת API בשרת האתר → בדיקת המנהל. שני הצילומים מראים את החלק Sheets→מאגר. מסלולי החברה מושהים, ואין טענה שנשלח טופס או שנוצר סידור דרך מסלול זה בניסוי.

מסלול Gmail המתוכנן: קריאת דואר → בדיקת כפילות → שמירת המקור → חילוץ AI → המרה ל-JSON → שמירת החילוץ → בדיקת תנאי מענה → אישור קבלה בעברית → שמירת מזהה המענה. האישור אומר שהפנייה התקבלה לבדיקה; אינו אישור שירות. ספק, חיבור ומודל AI במודול 4 של מסלול החברה עדיין ממתינים להגדרת הבעלים. מסלול ההדגמה המקושר ל-Make AI Provider הוא תרחיש נפרד ואינו מגדיר את מסלול החברה.

שרת האתר קורא את Make Data Store באמצעות מפתח שרת פרטי; הוא אינו נמסר בקוד או בתמונות. קובצי make-reference הם תיעוד עם מצייני מקום, ולא blueprint רשמי שאומת לייבוא. אין בתמונות הוכחה להעברת הרשאות Google לחשבון אחר.

## מה הוכח בניסוי

קלט טקסט מלאכותי ידני → Make AI Provider → JSON → מאגר בדיקה → קליטה אוטומטית בשרת Desktop כבקשה pending עם חילוץ validated. הקריאה המאומתת מהשרת החזירה HTTP 200 וגרסת מצב 2. בקשה נוספת עם JSON שגוי נשמרה לבדיקה עם אזהרה. זמן Make שנצפה היה 6.472 שניות וצריכה 5.89 קרדיטים; ה-ROI הוא מודל הנחות.

שלושת תרחישי Gmail/Forms של החברה נשארים Inactive. ההדגמה המלאכותית פועלת לפי דרישה בלבד. לא נבדקו קבלת Gmail אמיתי, הגשת Forms, שליחת מענה, אישור מנהל, יצירת עבודה או שיבוץ בניסוי זה. הקלטת המסך עדיין חסרה; דבר לא הוגש במודל.
