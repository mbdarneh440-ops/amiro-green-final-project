# קובץ בקשות הדואר במחשב

זו תוספת מקומית לפרויקט **אמירו גרין**: היא שומרת עותק מסודר של בקשות דואר, ובו שם, טלפון, דואר, ארגון, פרטי הבקשה, מקום האירוע, תאריכים ושעות, לצד טקסט ההודעה המקורי. `requests.json` הוא המאגר המקומי, ו-`requests.csv` הוא עותק שניתן לפתוח ב-Excel. כאשר `render-xlsx.mjs` והספרייה שלו זמינים, נוצר גם `requests.xlsx` מאותו מאגר.

ההפעלה המסחרית נשארת **כבויה** בהתאם לבקשתך. התוספת אינה קוראת את הדואר ישירות, שולחת תשובות או מתחילה עם הפעלת Windows. קריאה אמיתית בהמשך תהיה ממאגר הבקשות ש-Make מכין. הדוגמה המצורפת היא נתונים מלאכותיים להדגמה האקדמית, ולא הודעות לקוחות או ניסוי AI חי.

## ההדגמה למרצה עכשיו

פתחו `START-DEMO.ps1` באמצעות PowerShell, או הפעילו:

```powershell
node mirror.mjs --demo --input demo-records.json --out data-demo
```

פתחו `data-demo/requests.xlsx` אם נוצר, או `data-demo/requests.csv`. הדוגמה מציגה בקשה מלאה, בירור שחסרים בו פרטים ושינוי. טלפון שלא נמסר נשאר ריק. כל מידע שמגיע מ-AI חייב להיות נתמך בציטוט מהדואר; מידע שלא אומת מסומן בהערה. העמודה **סוג הנתונים** מציינת שזו דוגמה.

בקובץ XLSX, הגיליון **הבקשות** מיועד לרשומות העבודה האמיתיות, והגיליון **דוגמה להדגמה** נפרד לצורכי הצגה. במהלך ההדגמה גיליון הבקשות נשאר ריק ומספר רשומותיו אפס. ניתן לפתוח ישירות את הדוגמה המוכנה `בקשות אימייל.xlsx`, ללא חיבור כלשהו. פתיחת הקובץ אינה מפעילה סנכרון.

השם נלקח משם האדם המופיע בטקסט ההודעה אם הוא מתועד, אחרת משם השולח בכותרת הדואר. מקור השם מוצג במפורש. שם הארגון הוא עמודה נפרדת. שדה פרטי הבקשה מציג ציטוט מאומת של הבקשה; אם לא הגיע ציטוט, מוצג נושא ההודעה, והטקסט המלא נשאר זמין. הודעות שינוי וביטול אינן משויכות אוטומטית לבקשה קודמת; המנהל צריך לזהות את הבקשה המתאימה.

## בעת הפעלת הפרויקט בהמשך

לאחר אישור המרצה ובעל החברה, יש להפעיל את מסלול Make על דואר החברה ולהגדיר הרשאת קריאה למאגר הנתונים. האחראי משתמש בעוזר הגדרת הבעלים כדי לכתוב `.env` בתיקיית האתר שנבחרה. המשתנים הנדרשים הם `COMPANY_MAILBOX`, `MAKE_API_TOKEN`, `MAKE_DATA_STORE_ID`, וכן `MAKE_ZONE` אם האזור שונה מ-`eu1.make.com`. `MAKE_SYNC_ENABLED=false` נשאר כך עד שהבעלים בוחר הפעלה מפורשת לאחר הבדיקה. אין להכניס מפתח לקוד, לקובצי הבקשות או לחבילת המסירה. החבילה אינה כוללת מפתח כלשהו.

קריאה אחת:

```powershell
.\START-LIVE.ps1 -Project "C:\נתיב\wardiya-web" -Once
```

עדכון כל 15 דקות, רק כל עוד החלון והמחשב נשארים פעילים:

```powershell
.\START-LIVE.ps1 -Project "C:\נתיב\wardiya-web"
```

המשגר קורא את `.env` שהבעלים בחר עבור ההפעלה הזו בלבד, בלי להריץ את תוכנו כפקודות. הוא מקבל רק חמישה משתני Make נדרשים ומונע התחלת חיבור אם `MAKE_SYNC_ENABLED` אינו `true` או אם דואר החברה, המפתח או המאגר אינם תקינים. אינו מעביר מפתח AI או מפתחות מסביבת הסטודנט לתוכנית המעקב. הנתונים נשמרים ב-`data-live` לצד הכלי, בנפרד מ-`data-demo`. אפשר לבחור תיקייה קבועה אחרת:

```powershell
.\START-LIVE.ps1 -Project "C:\נתיב\wardiya-web" -Out "C:\Company\EmailRequests"
```

הפקודה המקבילה באמצעות Node ישירות:

```powershell
node start-live.mjs --project "C:\נתיב\wardiya-web" --out "C:\Company\EmailRequests"
```

לעצירה לחצו `Ctrl+C`. בקשה חדשה תופיע בקובץ רק לאחר שהגיעה למאגר Make. התוכנית אינה משתמשת ב-AI ואינה שולחת דואר; היא מקבלת פרטים שנשמרו במסלול Make. חיבור חשבון Google, הפעלת התרחישים והיתרה בתשלום מנוהלים ב-Make. הגדרת כתובת הדואר והמפתח כאן אינה מעניקה הרשאות Google. הגדרות Make בפועל והרשאותיהן לא נבדקו בתוספת הזו, משום שההפעלה המסחרית נדחתה. קובצי ההדגמה אינם מעידים על חיבור אמיתי לדואר, ואין הפעלה עם עליית Windows.

המשגר דורש Node.js 22 ומעלה. קריאת JSON ויצירת CSV אינן דורשות חבילות נוספות. Excel המעוצב הוא אופציונלי: אם הספרייה חסרה או הקובץ פתוח, JSON ו-CSV ממשיכים להישמר עם אזהרה ש-XLSX לא עודכן. עותק XLSX הקודם נשאר ניתן לפתיחה ועשוי להיות לא מעודכן; סגרו אותו ובצעו עדכון מחדש לאחר הכנת הספרייה. שימוש מפורש ב-`--xlsx-renderer` הופך כשל במייצא לכשל נדרש; האפשרות המוגדרת כברירת מחדל היא אופציונלית.

אפשר גם לייבא קובץ JSON שהוכן מהמאגר ללא חיבור:

```powershell
node mirror.mjs --input records.json --out data
```

הקלט יכול להיות `{ "records": [{ "data": { ... } }] }` או מערך רשומות. בכל בקשה נדרשים `sourceId`, `sender`, `subject`, `body`. הפרטים האופציונליים `requesterName`, `receivedAt`, `ackState`, `extractionJson` נשמרים. שמות שדות החילוץ תואמים לטיוטת Make, ובהם `contact_name`, `contact_phone`, `request_summary`, `source_evidence`.

## שמירת נתונים והערות

לכל הודעה מזהה מקור ייחודי. קריאה חוזרת מעדכנת את השורה הקיימת ולא יוצרת כפילות. הבקשות הישנות נשארות בעותק המקומי גם אם המאגר חוזר ריק או אינו מציג אותן עוד. כשל בחיבור או רשומה לא תקינה אינם גורמים לשמירת תשובה חלקית, והקבצים הקודמים נשארים.

החלטת מנהל אינה מוסקת מ-AI או מאישור הקבלה. אם לא התקבלה החלטה רשמית מהמקור, השדה שלה נשאר ריק. ניתן לתעד הערה או מצב מקומי במפורש:

```powershell
node mirror.mjs --annotate gmail:MESSAGE_ID --notes "יצרתי קשר עם הלקוח" --manager-status "ממתין לאישור מנהל" --out data
```

ההערות והמצבים המקומיים נשמרים ב-JSON ואינם נמחקים בעדכון. עריכה ידנית ב-Excel או ב-CSV אינה חוזרת למאגר JSON; יש לתעד אותה באמצעות הפקודה שלעיל כדי שתישאר אחרי עדכון. המצב המקומי אינו משנה את האתר ואינו מהווה אישור רשמי בו.

סגרו את קובץ Excel/CSV בזמן עדכון. התוכנית כותבת לקובץ זמני ומחליפה אותו לאחר סגירתו; אינה מוחקת את הקובץ הישן לפני שהחדש מוכן. JSON הוא המאגר הראשי. אם Excel חוסם עדכון של עותק התצוגה, מוצגת אזהרה והעותק הקודם נשאר; הפעילו שוב לאחר סגירת הקובץ. CSV משתמש ב-UTF-8 ומגן על התאים מפני הפעלת נוסחאות שמגיעות מהדואר. טלפונים נשארים טקסט ב-JSON וב-XLSX; ב-CSV מספרים המתחילים באפס מקבלים בתחילתם סימן `'` כדי לשמור על האפס בעת פתיחה ישירה ב-Excel.

אם התוכנית נסגרה בפתאומיות והופיעה אזהרת נעילה, סגרו חלונות אחרים שמפעילים `mirror.mjs`, מחקו רק את התיקייה הריקה `.sync-lock` שבתיקיית הנתונים והפעילו מחדש. אין למחוק `requests.json` או קובצי בקשות. מומלץ לגבות את תיקיית הנתונים לפי מדיניות החברה, משום שהיא מכילה פרטי לקוחות במחשב.

## דרישות ובדיקת התוספת

קריאת JSON ועדכון CSV דורשים Node.js 20 ומעלה, ללא התקנת חבילות. יצירת Excel מעוצב דורשת את המייצא המצורף ואת ספריית הגיליונות בסביבת Codex; CSV נשאר זמין במחשב אחר בלעדיה.

ניתן להגדיר את תיקיית החבילות ב-`ARTIFACT_NODE_MODULES` אם היא נמצאת בנתיב אחר. המייצא תומך אוטומטית בסביבת Codex הנוכחית. תיעוד נקודת קריאת הרשומות והרשאת `datastores:read` מופיע ב[תיעוד Make הרשמי](https://developers.make.com/api-documentation/api-reference/data-stores/data), ופרמטרי הדפדוף ב[תיעוד הדפדוף](https://developers.make.com/api-documentation/pagination-sorting-filtering/pagination-and-sorting). מבנה הממשק נבדק בתיעוד; החיבור לחשבון בפועל נדחה.

```powershell
node --test mirror.test.mjs
node --test start-live.test.mjs
```

הבדיקות משתמשות בנתונים מלאכותיים ובחיבור מדומה בזיכרון; אינן מתחברות לחשבון כלשהו. הן מכסות מניעת כפילויות, שמירת הערות, השארת טלפון חסר ריק, אימות ציטוטים, הגנת Excel, קריאה בדפים ושמירת המאגר הקודם בעת כשל.
