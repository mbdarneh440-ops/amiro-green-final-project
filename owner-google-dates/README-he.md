# עדכון תאריכי זמינות העובדים מחשבון הבעלים

זוהי חבילה **שהוכנה אך לא הותקנה ולא הופעלה ב-Google**. `AvailabilityDates.gs` מתחיל בתצוגה מקדימה בלבד, ולא נוצר מפעיל יומי. לאחר הגדרה ובדיקה של הבעלים, Google מפעיל אותו בענן בלי צורך לפתוח Codex או להשאיר את המחשב פועל.

הקוד מחשב את יום ראשון של השבוע הנוכחי לפי התאריך הנוכחי ב-`Asia/Jerusalem`, ומציג את התאריך `DD/MM/YYYY` לצד שבעת הימים. השינוי המותר הוא בשורות שאלת checkbox grid הקיימת ובכותרות `E1:K1` בלבד. הוא אינו כותב בתאי התשובות ואינו משנה את עמודת D ההיסטורית, נוסחת L2, הרשאות הטפסים, הפרסום שלהם או החיבור ל-Make. הוא אינו מעדכן את תיאור הטופס; תיאור ידני שמזכיר שבוע מסוים דורש בדיקה נפרדת.

הקבצים: `AvailabilityDates.gs`, ‏`appsscript.json` לאזור הזמן ולהרשאות, ו-`PROVENANCE.md` למקורות ולמגבלות הבדיקה. המזהים הנוכחיים של טפסים א/ב כלולים; בהעברה לחשבון אחר עליו לקבל הרשאת עריכה, או שיש להחליף ב-`TARGETS` את מזהי העותקים החדשים ואת מזהה לשונית כל גיליון, `gid`.

## הגדרה חד פעמית

1. פתחו [Google Apps Script](https://script.google.com/) בחשבון הבעלים וצרו פרויקט עצמאי. העתיקו את המקור לקובץ הקוד, הציגו את קובץ ה-manifest בהגדרות הפרויקט והעתיקו אליו את `appsscript.json`. אין ליצור deployment או web app.
2. השאירו `DRY_RUN: true`, ‏`OWNER_CONFIRMED_COPY_TEST: false` ו-`ENABLE_DAILY_TRIGGER: false`. הפעילו `previewAvailabilityDates` והשלימו פעם אחת את אישור Google לחשבון הבעלים. הרשאות החבילה מיועדות ל-Forms, ל-Sheets ולניהול המפעילים של הפרויקט הזה; היא אינה משתמשת ב-Gmail, במפתחות API או בסיסמאות.
3. בדקו את יומן התצוגה המקדימה. אמורות להופיע בדיוק שתי שאלות, שם וטלפון, ואחריהן checkbox grid בשם `זמינות למשמרות`, עם שלוש עמודות `בוקר / צהריים / לילה` ושבע שורות רצופות מראשון עד שבת. אלה **תנאי אימות**, ואינם טענה שכל הפרטים נקראו ישירות מ-Google בזמן הכנת החבילה.
4. לשונית התשובות צריכה להתאים למבנה A:L: זמן, שם, טלפון, השבוע הישן ב-D, ימים E:K, ואז `שבוע אוטומטי` ב-L. נוסחת L2 הקיימת צריכה להתאים לנוסחה המתועדת. אזור הזמן של הגיליון חייב להיות `Asia/Jerusalem`. בכל אי התאמה הקוד נעצר בלי לתקן. אין לשנות את אזור הזמן ההיסטורי או להחליף את נוסחת L רק כדי לעקוף שגיאה; בדקו קודם את מקור התשובות והנוסחאות.
5. **לפני ההפעלה, בדקו זוג ניסוי של טופס וגיליון מקושרים באותו מבנה**, עם תשובה מלאכותית קודמת. השתמשו בפרויקט Script נפרד ובמזהי העותקים. הגדירו את שורות הטופס ואת כותרות E:K לשבוע קודם כך שהתצוגה המקדימה תראה `wouldChange: true`; שבוע שאין בו שינוי אינו בודק שינוי שמות שורות. בפרויקט הניסוי בלבד הגדירו `OWNER_CONFIRMED_COPY_TEST: true` ו-`DRY_RUN: false`, והפעילו `applyAvailabilityDatesOnce`. ודאו שהתשובה הקודמת, D ו-L2 לא השתנו, שלא נוספו או זזו עמודות, ושהטופס והגיליון מציגים את השבוע הנוכחי. אם אי אפשר ליצור עותק באותו מבנה או מופיעות עמודות שנשמרו או נוספו, השאירו את חבילת הייצור בתצוגה מקדימה.
6. לאחר הצלחה, עדכנו את המזהים בפרויקט הייצור, הגדירו `OWNER_CONFIRMED_COPY_TEST: true` ו-`DRY_RUN: false`, הפעילו ידנית `applyAvailabilityDatesOnce` ובדקו את התוצאה. התקנת המפעיל דורשת הצלחה באותו יום ובאותם מזהים.
7. **עצרו תחילה את המעקב היומי הישן ב-Codex**, ואז הגדירו `ENABLE_DAILY_TRIGGER: true` והפעילו פעם אחת `installDailyAvailabilityTrigger`. הקוד מחזיר את מזהה המפעיל ומסרב ליצור כפילות. הפעילו `removeDailyAvailabilityTrigger` להסרתו; הפונקציה הזאת מוחקת רק מפעיל בשם הזה בחשבון הבעלים הנוכחי.

הפעילו מעדכן אחד בלבד: עצרו את מעקב Codex לפני הפעלת מפעיל Apps Script, והסירו את מפעיל Apps Script לפני חזרה למעקב Codex כחלופה. אף אחד מהם לא נעצר או הופעל בזמן הכנת החבילה. עד שהבעלים יגדיר הפעלה בענן, המעקב הנוכחי תלוי במחשב המשתמש וביישום Codex הפועלים.

## זמן והגנה על ההיסטוריה

המועד משוער, סביב **00:15–00:45** בשעון המקומי; Google אינו מבטיח הפעלת מפעיל זמן בשנייה מסוימת. השבוע הקודם עשוי להופיע לזמן קצר לאחר חצות ביום ראשון, ולהתעדכן בעת ההפעלה. מקור התאריך הוא שעון Google באזור שנקבע, ולא הגדרת השעון במכשיר אחר. [תיעוד מועד המפעיל ואזור הזמן](https://developers.google.com/apps-script/reference/script/clock-trigger-builder).

תאריכי התשובות הקודמות נשארים קשורים למועד שליחתן או לשבוע הישן ב-D; עדכון הכותרות אינו מחליף אותם בתאריך של היום. הקוד בודק טביעות של ערכי ונוסחאות A:L בשורות הקיימות לפני ואחרי הפעולה, ומאפשר הוספת תשובות חדשות בתחתית. `protectedRowCount` סופר את השורות המוגנות ועשוי לכלול את שורת L2 הריקה; `timestampRowCount` סופר שורות עם זמן שאינו ריק. הקוד אינו מתעד שמות, טלפונים או בחירות של עובדים.

אין עסקה אטומית משותפת ל-Forms ול-Sheets. ייתכן שהטופס או הכותרות כבר השתנו לפני כישלון בדיקה לאחר הכתיבה, ושהעדכון המובנה של Google מתעכב. תיעוד `setRows` מאשר שינוי של שורות השאלה, **אך אינו מבטיח** איך הגיליון המקושר משנה את שמות עמודות התשובות או שומר עליהן; לכן בדיקת העותקים היא תנאי להפעלה. הקוד נעצר בשינוי מבנה, מתעד fault וחוסם ניסיונות נוספים; הוא אינו משחזר תשובות או מתקן נוסחאות אוטומטית. בדקו את יומן ההפעלה ואת חשבון הבעלים, הסירו את המפעיל, ותקנו את הקישור או המבנה לאחר גיבוי. אחרי הצלחת התצוגה המקדימה הפעילו במפורש `clearAvailabilityDatesFaultAfterOwnerReview`, ולאחר מכן בדקו והתקינו מחדש לפי הצורך. [תיעוד שורות checkbox grid](https://developers.google.com/apps-script/reference/forms/checkbox-grid-item).

הבדיקה מוגבלת ל-20,000 שורות תשובות קודמות בכל לשונית. בחריגה הפעולה נעצרת ודורשת תוכנית שמירה ואימות מתאימה, במקום להתעלם מחלק מההיסטוריה. המפעיל פועל בהרשאות החשבון שיצר אותו; העברת בעלות דורשת אישור החשבון החדש ויצירת המפעיל מחדש אצלו. [תיעוד מפעילים הניתנים להתקנה](https://developers.google.com/apps-script/guides/triggers/installable).
