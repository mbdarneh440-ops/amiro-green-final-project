# הגדרת בעל החברה בהמשך

זהו כלי **מקומי לשימוש עתידי** להכנת הגדרות האתר עבור בעל החברה. החבילה אינה מכילה כתובת דואר חברה או מפתחות אמיתיים. הכלי לא התחבר לחשבון כלשהו ולא שינה את הגדרות האתר הקיים. ההפעלה המסחרית נשארת דחויה עד לקבלת אישור המרצה ובעל החברה.

הכלי אוסף את כתובת דואר החברה, מפתח Make, מזהה מאגר הבקשות ב-Make והאזור. מפתח AI ושם המודל שלו הם אופציונליים. לאחר אימות, הערכים נכתבים לקובץ `.env` בתוך **תיקיית האתר שבעל החברה בוחר**. המפתחות מוצגים ככוכביות בחלון אינטראקטיבי, ואינם מתקבלים בשורת הפקודה, בקובצי קלט או במשתני הסביבה של העוזר הזה. שום מפתח קודם אינו נקרא או משמש מחדש.

## שלושה שלבים לפני הפעלה בפועל

1. **חיבור חשבונות החברה ב-Make:** בעל החברה משתמש בחשבון Google של החברה ומחבר Gmail ו-Google Sheets/Forms באמצעות אישורי Google בתוך Make. אפשר להזמין אותו למרחב החברה המתאים או להעביר את הטיוטות לחשבונו. עליו לבחור מחדש את חיבורי Gmail/Sheets, המאגרים והטפסים הנכונים בכל תרחיש. מזהי החיבורים והמאגרים בטיוטת הסטודנט אינם מוכיחים הרשאות בחשבון החברה; במרחב חדש יש להחליפם במזהים החדשים. אין להזין סיסמת Gmail בכלי הזה. כתובת דואר החברה ומפתח Make לבדם אינם מעניקים הרשאת Google.
2. **הכנת הגדרות האתר:** הבעלים יוצר מפתח Make עם הרשאה לקריאת מאגר הבקשות במרחב החברה, ומברר בחשבונו את מזהה המאגר ואת האזור הנכון. הוא מפעיל את הכלי מקומית כדי להזין את הערכים בצורה מוסתרת. `MAKE_SYNC_ENABLED` ו-`AI_ENABLED` נכתבים **false כברירת מחדל**; הזנת מפתח אינה מפעילה את השירות. יש להפעיל מחדש את האתר לאחר שמירת `.env`. בשרת שפורסם, אחראי הפרסום צריך להגדיר את המשתנים גם בסביבת האירוח; יצירת קובץ מקומי אינה משנה את השרת שפורסם.
3. **בדיקה ואז הפעלה מפורשת:** האחראי בודק יתרת Make, הרשאות Google וחשבונות החברה, מנסה הודעה שבבעלותו ותשובת טופס לדוגמה, ומוודא שהרשומה מופיעה פעם אחת, שהפרטים החסרים מסומנים ושנדרשת בדיקת מנהל. הפעלת תרחישי Make מתבצעת בתוך Make לאחר הבדיקה. פתיחת הקריאה מ-Make או AI באתר נעשית באמצעות האפשרויות המפורשות שלהלן ואז הפעלה מחדש של האתר. הכלי אינו מתחיל תרחיש Make, שולח מענה או מפעיל מעקב מקומי אוטומטי. אישור הבקשות וסידור העבודה נשאר בידי המנהל.

## הפעלת עוזר ההגדרה

נדרשים Node.js 22 ומעלה וחלון PowerShell אינטראקטיבי. עברו לתיקייה זו ובחרו את **תיקיית האתר שמכילה `package.json`**:

```powershell
node configure-owner.mjs --project "C:\נתיב\wardiya-web"
```

או באמצעות המשגר המצורף:

```powershell
.\OWNER-SETUP.ps1 -Project "C:\נתיב\wardiya-web"
```

כשנשאלים על מפתח AI, אפשר ללחוץ Enter כדי לדלג עליו. כשנשאלים על מודל AI, השאירו את השדה ריק כדי להשתמש בברירת המחדל של האתר. אין לכתוב מפתחות בתוך הפקודות שלעיל. אין להכניסם ל-`owner-inputs.example.json`; הקובץ מסביר רק את שמות הקלט והכלי אינו קורא אותו.

אם `.env` כבר קיים, אפילו אם הוא ריק, הכלי נעצר לפני קריאת תוכנו או שינויו. **החלפה מלאה מחייבת אפשרות מפורשת**:

```powershell
node configure-owner.mjs --project "C:\נתיב\wardiya-web" --replace
```

`--replace` מחליף את כל קובץ `.env` בערכים החדשים המאומתים בלבד. אינו שומר מפתחות קודמים או משתנים לא מוכרים, ואינו יוצר גיבוי שעלול להכיל סודות של הסטודנט. אם יש משתנים נוספים הנחוצים בסביבת החברה, אחראי ההגדרה צריך לבדוק ולתעד אותם בצורה בטוחה לפני בחירה בהחלפה.

לאחר סיום הבדיקה ואישור ההפעלה, ניתן להכין קריאת Make בלבד:

```powershell
node configure-owner.mjs --project "C:\נתיב\wardiya-web" --replace --enable-make-sync
```

כדי להכין קריאת Make ו-AI יחד, הבעלים צריך להזין מפתח AI חדש ותקין השייך לו:

```powershell
node configure-owner.mjs --project "C:\נתיב\wardiya-web" --replace --enable-make-sync --enable-ai
```

הפקודות מבקשות מחדש את נתוני החברה וכותבות את הקובץ מקומית. הן אינן בודקות את המפתח, יוצרות חשבון או מנוי, מבקשות הרשאות Google או מוסיפות יתרה בתשלום. מפתח AI אינו דרוש להדגמה האקדמית שבה השירות כבוי, וגם לא לקריאת מאגר הבקשות המקומי בלבד.

## הקובץ והגנה מעשית

המשתנים המותרים בלבד: `COMPANY_MAILBOX`, `MAKE_API_TOKEN`, `MAKE_DATA_STORE_ID`, `MAKE_ZONE`, `MAKE_SYNC_ENABLED`, `AI_API_KEY`, `AI_MODEL`, `AI_ENABLED`. האזורים המותרים: `eu1.make.com`, `eu2.make.com`, `us1.make.com`, `us2.make.com`. אין להעתיק הגדרות כניסה לדואר או מזהה מרחב אחר כאילו היו הגדרות החברה.

קובץ זמני נכתב בתיקיית האתר, נסגר ונשמר לפני הצבת הקובץ הסופי. יצירה ראשונה משתמשת בקישור מקומי אטומי המונע החלפה אם הופיע קובץ נוסף במהלך ההגדרה; החלפה מפורשת משתמשת בהחלפה אטומית. אם מערכת הקבצים אינה תומכת בכך, ההגדרה נכשלת במקום לכתוב קובץ חלקי. קובץ `.env` והמפתחות שבתוכו צריכים להישאר במחשב החברה ובתיקייה המיועדת לה; אין לצרפם ל-ZIP המסירה או ל-Git. הכלי משתמש בהרשאות קובץ מוגבלות במערכות שתומכות בכך; אחראי Windows צריך להגן על גישת משתמשים לתיקיית החברה.

סגרו את האתר והפעילו אותו מחדש לאחר השינוי. מסלול החיבור הפעיל ומעקב מאגר הבקשות המקומי דורשים הגדרה עצמאית בסביבה שלהם; הכלי הזה מכין רק את `.env` של האתר. הודעת הצלחה בשמירת הקובץ אינה אומרת שדואר, Make או AI כבר פועלים; היא מאשרת יצירת הגדרות מקומיות ללא חשיפת המפתחות.

## בדיקת הכלי ללא חשבונות

```powershell
node --test configure-owner.test.mjs
```

הבדיקות משתמשות בערכים מלאכותיים בתיקיות זמניות בלבד. הן בודקות את הערכים, דוחות הזרקת שורות הגדרה, מוודאות שההפעלה חסומה כברירת מחדל, שהקלדת המפתחות מוסתרת ושקובץ קיים אינו מוחלף ללא אפשרות מפורשת או תוך שימוש מחדש במפתחות קודמים. אין חיבור לרשת בתוך הכלי.
