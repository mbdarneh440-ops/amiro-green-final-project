# ורדיה — הוראות הפעלה וקוד

מערכת בעברית לניהול עובדים, אתרים קבועים, אירועים, בקשות דוא״ל, שיבוץ ושעות עבודה. הנתונים ההתחלתיים הם נתוני הדגמה.

## הפעלה במחשב

1. נדרש Node.js בגרסה 22.13 ומעלה. במחשב הזה הקובץ מאתר אוטומטית את הגרסה המצורפת ל־Codex. npm מצורף לפרויקט ואין צורך להתקין אותו בנפרד. במחשב חדש ייתכן צורך בחיבור לאינטרנט להתקנת הרכיבים.
2. פתחו את הקובץ `הפעלה.cmd`. הוא מתקין רכיבים חסרים, מכין מסד נתונים מקומי ומפעיל את המערכת.
3. המתינו עד שהדפדפן נפתח אוטומטית. הקישור מודפס גם בחלון ההפעלה. השאירו את החלון פתוח בזמן העבודה.
4. דרך מסוף: `node scripts/start-local.mjs`. ההתקנה הראשונית מתבצעת אוטומטית. פתיחה חוזרת של קובץ ההפעלה פותחת את השרת שכבר פועל מאותה תיקייה.

הנתונים נשמרים ב־`.wrangler/state`; אין למחוק את התיקייה אם רוצים לשמור את העבודה. החשבון המקומי נפרד מחשבון האתר המתארח. ההפעלה המקומית אינה מפרסמת את האתר באינטרנט.

## היכן מכניסים מפתחות

פותחים את `.env` בעורך טקסט. אם הוא חסר, ההפעלה יוצרת אותו מתוך `.env.example`.

```dotenv
MAKE_API_TOKEN=
MAKE_ZONE=eu1.make.com
MAKE_DATA_STORE_ID=<DATASTORE_ID>
AI_API_KEY=
AI_MODEL=
```

`MAKE_API_TOKEN` הוא מפתח שרת לקריאת מאגר Make עם הרשאת `datastores:read`. אחרי שינוי מפעילים מחדש את `הפעלה.cmd`, שמעתיק את ההגדרות ל־`.dev.vars`. אין לשלוח מפתחות בצ׳אט או לשתף את קובצי ההגדרות.

הצ׳אט משתמש ב־OpenAI Responses API. לאחר מילוי `AI_API_KEY` והפעלה מחדש, שאלות שלא נענו מקומית נשלחות ל־AI. `AI_MODEL` ברירת המחדל היא `gpt-4.1-mini`. כשהאפשרות מסומנת, המודל יכול לחפש ברשת ומקורות מוצגים כקישורים. בלי מפתח פועלים רק הסברים מקומיים וחיפוש עובד. חילוץ הודעות הדוא״ל והשיבוץ פועלים לפי כללים, בלי AI. באתר מתארח מגדירים סודות שרת בנפרד; קובץ מקומי לא מעדכן אותם.

## הכנסת נתונים וניסוי

שלוש תבניות CSV נמצאות ב־`public/templates`: עובדים, אתרים קבועים ואירועים. במסך העובדים או האתרים בוחרים ״ייבוא קובץ״, בודקים תצוגה מקדימה ומאשרים. אותו קוד רשומה מעדכן נתונים קיימים. שאר נתוני ההדגמה אינם נמחקים בייבוא.

1. ב״בקשות לבדיקה״ פתחו את בקשת האירוע לדוגמה, השלימו תעריף, שמרו טיוטה ופתחו שוב לאישור.
2. בסידור העבודה בחרו את שבוע 21.09.2026, לחצו ״הצעת שיבוץ״, בדקו חוסרים ואשרו.
3. ב״שעות בפועל״ דווחו שעות ואשרו אותן. בדוחות הכספיים עברו בין תחזית לביצוע מאושר.

מסך העובד הוא כרגע תצוגה בחשבון המנהל; חשבונות אישיים לעובדים עדיין אינם פעילים.

## גבולות ההדגמה

השיבוץ בודק זמינות מאושרת, הכשרה, חפיפות, מנוחה, מעבר בין אתרים ומכסת שעות. הכיסוי מחולק למשמרות של עד שמונה שעות; אין הבטחה לפתרון מיטבי. משמרות של אתר ביום שבו כבר דווחו שעות נשמרות בתכנון מחדש, ויתר הימים ניתנים לעדכון.

הדוחות משתמשים בתעריפים שנשמרו במשמרת. שיעור מס והוצאות הם הנחות לעריכה; מס חסר מוצג כחסר. אין חישוב מלא של שעות נוספות, מדרגות מס או מעבר שעון קיץ וחורף. יש להשלים אותם לפני שימוש עסקי בפועל.

המערכת פועלת מקומית. היא לא פורסמה באינטרנט.

## יישום Windows

הקובץ `ורדיה.exe` פותח חלון עצמאי המבוסס על Microsoft WebView2. נדרשים Windows 64-bit, ‏.NET Framework 4.6.2 ומעלה, WebView2 Runtime ו־Node.js. הקוד נמצא ב־`desktop/Wardiya.cs`. נבנה בהצלחה, אך הפעלתו מתוך סביבת הפיתוח נחסמה במדיניות Application Control ולכן פתיחת החלון טרם אומתה. אין לבטל הגנות Windows. אם הארגון חוסם יישומים לא חתומים, נדרשת חתימה או אישור דרך מנהל המחשב. `הפעלה.cmd` נשאר מסלול פתיחה בדפדפן.

השיבוץ החדש מוצג לפי יום ואתר, לפי עובד ובדיווח שעות. חיפוש עובד בראש המסך מציג פרטים וזמינות. כפתור ״עזרה״ פותח צ׳אט בצד.
